§3 — Media upload — confirmation + one honest gap
Wire shape — confirmed:

Endpoint: POST /api/uploads/request-url ✓
Request body: { name, size, contentType } ✓
Response: { "uploadURL": "https://storage.googleapis.com/...", "objectPath": "/objects/uploads/<uuid>", "metadata": { name, size, contentType } }
Matches what you have, except we currently do not return publicUrl — uploaded objects are private by default. If/when you need a public-readable variant for a "preview from Ouvro" flow, we'll add it as an opt-in ?public=true query param. Today, the snag detail view in Archidoc fetches the object via signed reads on demand, so you don't need it for the smoke run.
The returned objectPath is exactly what you should pass into media[i].objectPath (or media[i].remoteKey) on the snag intake. Round-trip verified.
Honest gap — please flag it on your side too: the upload-URL endpoint on staging is not Bearer-protected today (it predates the OUVRO partnership; it's behind the broader Replit deployment auth, but not behind the OUVRO key specifically). For the smoke run this is fine — your BFF holds the only key that can post to /api/ouvro/snags, and that's where we enforce isolation. Before broad rollout we'll add requireOuvroApiKey to /api/uploads/request-url as well. Tracking that as the only blocker for "GA-ready"; happy to coordinate the cutover with you so your BFF flips to Bearer-on-uploads in the same release.
